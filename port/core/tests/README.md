# The core's tests

Two programs, built with g++ from `../src/*.cpp` and the files here. No game and no emulator: the host is 24 MiB of
plain memory, and the game is a stand-in whose steps are a hash of its inputs.

| File | What |
|---|---|
| `run.sh` | Builds and runs the tests (`run.sh [build folder]`); part of the full check (`scripts/check.sh`). Its last line: `N checks, M failed`. The tests run every time; the test program is compiled only when something it is built from has changed: it is kept outside the repository (`~/.cache/fzgx-core-tests`, `FZGX_CORE_TESTS_CACHE`) under a hash of every source, every header the compiler says they include, the flags, this script and the compiler, and taken from there only under exactly that key and with the bytes that were kept. Its first line says which it was. The sources are compiled by their names from `port/core` and the program runs from there, so it holds no path of a checkout: a test finds its files from where it runs |
| `main.cpp` | The test program: the order the tests run in, and the time limit of each. `test_core --save-options FOLDER` is no test: the game's reader of a saved game on a folder, one line and a status, for `port/gates/runs/controller-setup-run.sh` |
| `harness.h` | What the tests share: `CHECK`, the host, the stand-in game and race, the temporary folder, a replay made by hand |
| `parts.h` | The other parts' files the tests read (`ProtocolFile`, `LauncherFile`): the protocol's and the launcher's checkouts, which `run.sh` takes from `port/setup/pins.tsv` |
| `test_guest.cpp` | The game's memory and the data window; the small helpers (SHA-1, strings, base64, UDP) |
| `test_rollback.cpp` | The undo log, the locked cache in it, the rollback interface, the checksum, the data window left alone |
| `test_rollback_state.cpp` | The list of rollback's state (`port/facts/rollback-state.tsv`) against the undo log: every byte changed, restored, and judged by its row |
| `test_files.cpp` | A launch file's match and a replay read into a race; every set-up and file that is refused |
| `test_save.cpp` | The player's controller options, read from a save made here (no game's bytes), and every save that is refused: by its bytes, by a file that does not open or read, by which file of the folder is the save; 4,000 saves damaged at random, none taken with a value the game's screens cannot write |
| `test_save_race.cpp` | A race's frame tick writing the player's controller options into the game (the standard controller's three blocks; again after the game's own reset; not in a playback, not from a refused save); the blocks under rollback, and outside the checksum |
| `save_files.h` | What those two share: options the game's screens can write, and a save file made of them |
| `test_stats.cpp` | A race's stat pack read from a match: the made-up pack both sides' tests share, every pack and entry that is refused, the ranges' table against the handbook's page, every case of the protocol's `protocol/tests/vectors/stat-cases.tsv` (the list of values the launcher's check is held to as well; `stat-cases.py` beside it writes it from the handbook's table; the protocol's files are found through `FZGX_PROTOCOL_DIR`, `run.sh`); a recording's version 3 |
| `test_stats_race.cpp`, `stat_packs.h` | The pack in memory: laid over made-up car data and nothing else, not written where the loader's table does not stand, no byte touched without a pack, compared once the race runs; under rollback; the go refused on a wrong table or weight |
| `test_out_test.cpp` | Whether a machine is out (`out_test.h`, the game's own verdict): every case of `port/image/tests/out-cases.tsv`, the list the image's text and its Python model are held to as well (`test_out_test.py`); the reader's words from a made-up game, nothing written |
| `test_options_screen.cpp` | The start that opens the game's controller options: nothing asked before the title stands after its card sequence, Options then the controller menu asked for once each, the sub-screens and the game's save are no leaving, B stops the game once; the other ways out; the launch file's key |
| `test_launch.cpp` | The launch file's reader: every key into its setting, no "debug" part leaves every test setting off, every refusal by the key's name; every file of `port/configs` is one it takes; the texts the launcher writes, the game window's two members among them |
| `test_place.cpp` | The game window's kept place: the file's text there and back and every text that is no place, the file written and read, whether a kept window is put back on made-up monitor layouts (a second screen left of or above the first, one that is gone, a moved taskbar); and the wait for a console's moment: its three ways, its 4 ms limit, none in a single-core start |
| `test_panel.cpp` | The panel before a race: LOADING from a start until the course intro's phase and never again, WAITING FOR PLAYERS at the gate after a quarter of a second and down at the go, its lines with and without a count, the meter's art missing from a host without the game's files, and a session held at the gate telling its host |
| `test_panel_art.cpp` | The panel's art: a packed file unpacked and what is refused, a texture's pixels of both kinds, a picture scaled for the screen, the load's progress (the first drain by bytes, the rest by fields, never back) |
| `test_screen.cpp` | The plain state behind the game's window: what of its place is kept and when (a drag, maximised, full screen, a window being put back), the asking for the backend's own full screen (asked once, held, given back, refused), and what each way of showing a picture needs of the emulator |
| `test_pace_delay.cpp` | When steps run at an input delay of 0 and 1 beside 2: the schedule's band, no late input, and the catch-up rule's depth growing with the delay given up (a relay three steps away, every prediction wrong, a host that never makes time up) |
| `test_launch_latency.cpp` | How a picture is shown and a race's input delay as the launch file carries them: `present` (`console` unless `field` or `copy`, the two kept for comparison, which the log calls test settings; refused under `debug`), the delay as the player's setting, 0 to 2 and refused above, `verticalSync`, and the sentences the log gets |
| `test_launch_widescreen.cpp` | True widescreen as the launch file carries it: off unless asked, the image's word the game's own 16:9 aspect to the bit, refused without the game's 16:9 mode or as a word not true or false |
| `test_launch_taskbar.cpp` | The launch file's `taskbar`: the launcher's id, program file and name, each held to what Windows may be given (an id of ASCII letters, a program file by its whole local path ending in .exe, one line each); from a file, a program that is not there is refused |
| `test_strip.cpp` | The game window's strip: where its buttons, name and frame rate are at two scalings and in narrow windows, none in full screen, and what each point of the window is (bar, button, the edge that resizes, picture); the frame rate found at the end of a window's title |
| `test_relay.cpp` | A match race against a relay that is the test: a broken clock, seats and frames of no race, the race's end |
| `test_race_end.cpp` | The race's end held until it is official: five races whose last finisher is predicted wrong, early and late; the results phase begins once, before the same step as on the official inputs alone, and every step the recording holds is the official race's (one race's frame is cut below the steps the session had counted as run) |
| `test_pace.cpp` | When steps run: a race on a host that paces as the emulator does, against a relay that keeps and closes inputs as the real one, in time the test moves: the game stays within its schedule, falls back by frames without a new step (on a host with time to spare, and on three that hold the pace with long and short frames in turn), sends one input for a frame, computes the same; and a host too slow for the pace sends its inputs in time |
| `test_summary.cpp`, `paced_race.h` | The line a race leaves in the player's file: a paced race run to its end and into its results, the line's fields by phase; its four ends, the tallies' medians, the file kept to its last lines, a file that cannot be written, is too large to be the game's or cannot be read; a summary that throws costs no replay. The header: the paced race's settings and results, for this file and `test_pace.cpp` |
| `test_spectate.cpp` | A paced race whose local seat goes out, every prediction wrong, with the relay's clock as the host's, 1.2% slow and 3% fast: one step a frame from there, at 0.99 (lower on the slow clock) until in lockstep with the slack in hand, no rollback after, the official race, no late input, the pad until lockstep and the neutral record after; a knock-out taken back (after 30 frames, and in the frame that would go into lockstep): racing again with the pad, never in lockstep; a seat over the line; a two-second stall made up at up to 1.25; a wait raising the slack; the race's end while still falling behind; and the launch file's switch that keeps it rolling back |
| `test_recording.cpp` | A recording played back with rollbacks forced and with late inputs; a recording written and read back |
| `test_native_form.cpp` | The native form: its bundle, what is in the window before boot, the patch list written into the code |
| `mode_bench.cpp` | The mode interpreter's bench, outside the suite: its cost on a fake race, and a hash of its state at each run to hold two builds of it to the same bytes; built and run by hand |
| `fuzz.sh` | Builds the fuzzers with the sanitizers and runs both (`fuzz.sh [seconds] [seed] [folder]`); run by hand |
| `fuzz.h` | What the fuzzers share: the host, the stand-in game, a bundle |
| `fuzz_replays.cpp` | Replay files changed in hostile ways, read by both readers and played back; the program's `main` |
| `fuzz_relay.cpp` | A match race against a relay that also sends what no relay should |
| `fuzz_launch.cpp` | Launch files changed in hostile ways, read and set up; run with every replay of the replay fuzzer |

A test is a function `Test...` in a `test_*.cpp`, declared and called in `main.cpp`.
